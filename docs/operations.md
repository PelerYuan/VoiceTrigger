# 验收与维护

## 上线前清单

- 宿主机及容器识别到 P4，完整模型推理成功。
- 摄像头音轨、说话距离、增益和网络断线恢复已验证。
- 实际名字、昵称、相似发音及电视背景声均有测试记录。
- 用命中时间减捕获时间观察端到端处理等待，另记录 CPU/GPU、内存和队列丢弃。
- 连续运行至少覆盖一个实际使用周期，检查磁盘增长和重启情况。
- 关闭全量转写调试，确认凭据、录音和事件不出现在公开仓库。

## 验证层次

| 检查 | 可以证明 | 不能证明 |
| --- | --- | --- |
| 单元 / 模拟管线测试 | 匹配、分段、冷却、事件及错误传播逻辑 | 真实语音识别准确率 |
| 文档构建 / 链接检查 | 文档可构建、本地链接和导航存在 | 设备部署成功 |
| Docker CI smoke test | 镜像能构建，依赖可导入 | P4 推理兼容性 |
| check 诊断 | 报告当前可用计算类型 | cuDNN / 完整推理通过 |
| 真实设备验收 | 目标环境中实际效果 | 对其他环境的性能保证 |

## 日常操作

```bash
docker compose logs --tail=100
docker compose exec voice-trigger tail -n 10 /events/triggers.jsonl
nvidia-smi
docker compose restart voice-trigger
```

重启会清空冷却状态。不要用 `docker compose down -v` 进行普通停止，它会删除模型和事件命名卷。

## 升级与回滚

记录旧镜像 ID 或保留旧镜像标签及私有配置。升级前跑核心测试、容器构建和真实 P4 测试，再替换镜像。不要同时升级驱动、CUDA/cuDNN、模型和程序，否则难以定位兼容问题。

事件格式变更必须同步文档、Schema 和消费者。推理依赖固定是为了兼容，不代表无需安全更新；更新时单独测试 P4。
